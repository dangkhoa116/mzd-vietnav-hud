VIETNAV HUD - in-car steps (TouchTune USB install)
====================================================

WHAT YOU NEED
  * A FAT32 USB stick built by:  python installer/build-kit.py <stick>
    The kit ships BOTH mods, ready to install:
      AA      oem-aa-mod 0.10.0 binaries (Android Auto -> HUD, GAL 1.6)
      CARPLAY mazda-carplay-hud bridge (ilshyma build: km/h + VN fold)
    Payload provenance + md5: vietnav-payload/PAYLOAD-SOURCES.md

INSTALL (touch, no keyboard)
  1. Ignition ON (engine running or ACC), radio fully booted.
  2. Insert the stick. The update dialog appears after a few seconds.
  3. Tap INSTALL. The VIETNAV HUD menu appears (status on top, Vietnamese
     and English):
       CAI DAT   -> pick a target: AA / CARPLAY / CA HAI (both), then
                    CAI DAT again to confirm (HUY = nothing changes)
       THU THAP  -> writes vietnav-collect-<date>.tgz to the stick
       GO BO     -> (when installed) GO BO again to confirm, then removes
                    what is installed
  4. After CAI DAT, power-cycle the car once: ignition off, lock it, wait
     about 10 minutes, start it again. The iPhone is only told the car
     takes navigation (NaviSupported) on a fresh start. Then:
       AA:      plug in an Android phone, start navigation
       CARPLAY: connect an iPhone, start navigation. Apple Maps can be
                started anywhere. WITH VIETMAP LIVE: search and press
                start ON THE CAR SCREEN - a route started on the phone
                never creates a CarPlay navigation session (proven by
                hooks on a jailbroken iPhone: zero maneuver objects),
                so there is nothing for the HUD.
     The HUD should show the turn arrow + distance; street names fold
     Vietnamese diacritics to the HUD font automatically.

IF NO DIALOG APPEARS
  * Pull the stick, wait 10 s, reinsert. Check the stick is FAT32 and its
    root has jci-autoupdate + the .up trigger file.
  * Terminal fallback (root shell; the stick is /tmp/mnt/sda1 with the
    keyboard in the other port). Without --yes it is a dry run:
      sh /tmp/mnt/sda1/vietnav-install.sh all           (check, change nothing)
      sh /tmp/mnt/sda1/vietnav-install.sh aa --yes      (Android Auto only)
      sh /tmp/mnt/sda1/vietnav-install.sh cp --yes      (CarPlay bridge only)
      sh /tmp/mnt/sda1/vietnav-install.sh all --yes     (both)

THU THAP (only when something goes wrong)
  * Not needed before installing: the installer checks the unit itself and
    stops before any change if something does not look right.
  * If CAI DAT fails or the HUD stays blank, tap THU THAP and send the
    .tgz (firmware + sm.conf + the AAP XMLs) together with the
    vietnav-*.log files from the stick.

UNINSTALL
  * Same menu, GO BO. A power cycle finishes it if smctl could not
    restart a service.

LOGS
  * Every run leaves its log on the stick: vietnav-touch.log,
    vietnav-install.log, vietnav-rollback.log. Bring the stick home.

ONE STICK, SEVERAL KITS
  * The stick may also carry the TPMS and wireless-CarPlay kits. Tapping
    INSTALL asks which kit - the chooser shows the three standard buttons
    (TPMS / CARPLAY / VIETNAV) whenever at least two of them are on the
    stick, with a line per kit saying whether it is installed on the car
    (DA CAI / CHUA CAI); a kit that is not on the stick keeps its button
    and tapping it says so on screen. The cancel is the HUY inside each
    kit's menu (the CarPlay kit asks BAT DAU / HUY first). After TPMS or
    VIETNAV, tap its last message away and LAM TIEP / XONG asks whether
    to pick another; the CarPlay kit restarts the unit, so it is the last
    one.
    Each kit only touches its own files.
  * After the wireless-CarPlay kit's GO BO (rollback), this menu may say
    "CHUA CAI" again: tap CAI DAT to put the HUD lines back.

NOTES
  * KHONG HO TRO / NOT SUPPORTED: the unit's own binaries the mods hook
    into (blmjciaapa.so, aap_service, blmjcicarplay.so,
    libdevmgr_interface.so) are not the builds the mods were checked on
    (74.00.324A = 74.00.331). Nothing was changed. THU THAP and bring the
    stick home.
  * Installing on a unit whose jciCARPLAY/jciAAPA/aap_service block already
    has an environ_var from another mod: the installer STOPS before changing
    anything and says so in the log - sort the other mod out first.
  * A payload file with the wrong md5 (a damaged stick) also stops the
    install before any change: rebuild the stick. If a write fails
    half-way, the install puts back everything it had changed.
  * The CarPlay install sets NaviSupported=TRUE (what makes the iPhone
    stream maneuvers); rollback puts FALSE back only if it was FALSE.
